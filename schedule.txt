# NH 장중 회차 — 위험 → 수집 → 필요 시 세 AI 판단 → 집계 → 실행 → 체결 확인

평일 09~15시 매 정각, 이 폴더의 기존 .venv/Scripts/python.exe로 수행한다.
코드·패키지·스크래퍼·.env·전략·원장을 수정하지 않는다. 사용자에게 명령 입력을 시키지 않는다.
키·토큰·계좌번호·원장 전체를 출력하지 않는다.

1. INVESTMENT_POLICY.md·QUANT_STRATEGY.md를 읽는다. broker.MOCK=True와 QUANT_ENABLED를 확인한다.
   총 100만 원·국내만·5개 상한·종목당 상한 20만 원·현금 25만 원·손절 -4%·손실 10만 원 중단을 지킨다.
2. trade.py --scan을 먼저 실행한다. 일봉·뉴스·AI와 무관하게 보유 손절·계좌·미체결을 점검한다.
   이 단계는 모의 주문이 나갈 수 있다. 확인된 당일 미체결은 기존 코드가 1시간 후 잔량 취소를 한 번 요청한다.
   확정 전 예약 유지·접수/취소 불명 재전송 금지를 지킨다. 장이 닫혔으면 6단계로 간다.
3. collection-task.md로 뉴스·날짜 있는 일봉·비교 ETF·계좌·보유와 계산된 quant_context를 같은 입력에 고정한다.
   기업 발굴·사업/재무 보완은 일일 discovery-task.md다. 수집 실패면 결정서 주문을 보류하고 6단계로 간다.
4. cycle.py --gate로 판단 필요성을 점검한다. request이면 research-task.md의 새 독립 A/B/C 판단과 집계를 수행한다.
   skip이면 새 의견을 만들지 않는다. blocked 또는 필요한 투표의 실패/누락이면 실행을 보류하고 6단계로 간다.
   완료된 퀀트 근거·뉴스·기업 근거·보유/체결·누적 가격 변화·재평가에 필요한 변화가 있을 때만 새로 판단한다.
   같은 자료로 세 역할을 혼자 연기하지 않는다. 퀀트 양수만으로 결정서를 자동 매수로 만들지 않는다.
5. cycle.py --execute로 이번 수집·점검·세 응답 결정서의 일치를 확인한 뒤 주문 엔진에 전달한다.
   새 판단 실패 시 과거 결정서로 대신 주문하지 않는다. skip은 같은 기존 결정서의 원래 유효기간 안에서만 가능하다.
   trade.py --do·broker 직접 호출로 검사를 우회하지 않는다.
   현재가·예산·미체결·가격 상한·같은 신호일 재진입 금지는 다시 검사된다. -4% 손절이 우선이다.
6. trade.py --account로 실제 체결·잔고와 대시보드·로컬 평가 원장을 갱신한다.
   계산 초안·세 판단 원문·최종 결정·실제 체결을 구분한다. 관측 횟수를 독립 거래 수로 세지 않는다.
7. board.py를 재사용한다. 없으면 숨겨진 백그라운드로 띄운다.
   Windows Start-Process는 -WindowStyle Hidden·작업 폴더·절대경로를 사용한다.
   요약 한 줄, AI 판단 요청/생략/보류 또는 매매 이유 한 줄, http://127.0.0.1:8778 주소 한 줄로 보고한다.
   JSON·명령줄·개인 계좌 내역은 붙여넣지 않는다.

활성 예약은 일일 기업발굴과 장중 회차 둘이다. 별도 동시 기업선정 예약은 중지 상태를 유지한다.
손절은 매시간 점검이며 -4% 체결을 보장하지 않는다. 멈추려면 'NH 자동매매' 예약을 일시 중지한다.
