# NH 장중 멀티 워크 연결 담당

평일 09~15시 매 정각 이 폴더의 기존 .venv/Scripts/python.exe를 사용한다.
MULTIFLOW_PLAN.md·INVESTMENT_POLICY.md·workflows/COORDINATOR.md를 따른다.
코드·패키지·.env·전략·원장을 고치지 않는다. 모의 전용이며 키·계좌 원문은 출력하지 않는다.
총 100만 원·국내만·최대 5개·종목 상한 20만 원·현금 25만 원·손절 -4%·손실 10만 원 중단을 유지한다.

1. 모의 환경을 확인하고 flow.py --start mock으로 회차를 시작한다. 진행 중인 회차가 있으면 새 수집·판단을 겹치지 않는다.
   이 경우에도 모의 환경이 확인됐다면 연결 담당이 기존 trade.py --scan을 별도 실행해 위험 점검을 시도한다.
   기존 엔진 잠금으로 점검할 수 없으면 실패를 알린다. 이어 --account 조회만 하고 끝낸다.
2. risk 작업을 발급해 등록된 execution Work에 전달하고 완료 기록을 확인한다.
   기존 trade.py --scan이 일봉·뉴스·AI와 무관하게 위험·미체결을 먼저 점검한다.
   확인된 당일 미체결만 1시간 후 한 번 취소 요청하며 확정 전 예산 유지·불명 재전송 금지를 지킨다.
3. data 작업을 발급해 data Work에 전달한다. collection-task.md의 기존 읽기 전용 뉴스·시세·계좌 도구를 사용한다.
   이어 quant Work에 quant 작업을 전달한다. 같은 자료의 quant_context 재계산·봉인과 cycle.py --gate 점검을 한다.
4. quant 완료 기록의 gate가 request일 때만 A/B/C 작업을 발급해 각 등록 Work에 전달한다.
   각 Work는 voter-instructions.md와 같은 불변 입력만 새 fork_turns="none" 독립 세션에 준다.
   세 완료 기록을 모두 검증한 뒤 flow.py --aggregate FOLDER로 코드 집계한다.
   서로 답을 보지 않고, 세 응답 모두 유효하며 두 표 이상 일치해야 한다. 셋이 갈리면 보유다.
   blocked·실패·누락·만료면 신규 결정서 주문 보류다. 이전 결정을 대신 사용하거나 hold를 만들어 채우지 않는다.
   skip은 새 AI 판단이 아니다. 중요 변화가 없으면 세 호출을 생략한다.
5. execute 작업을 발급해 execution Work에 전달한다.
   내부 cycle.py --execute가 수집·gate·결정서 일치를 검증한 뒤 기존 주문 엔진을 호출한다.
   현재가·예산·미체결·가격 상한·같은 신호일 재진입 금지를 다시 검사한다.
   trade.py --do·broker 직접 호출로 우회하지 않는다. -4% 손절은 투표보다 우선한다.
6. 기존 trade.py --account로 체결·잔고·대시보드·평가 관측을 조회한다.
   실패 때도 이 조회만은 시도할 수 있다. 주문·관측·계획을 구분한다.
   Work 실패·시간 초과·결과 누락은 workflows/COORDINATOR.md의 alerts.py 실패 알림으로 남긴다.
   flow.py --finish FOLDER로 끝낸다. 오류로 종료해도 성공한 회차라고 보고하지 않는다.
7. board.py를 재사용한다. 없으면 절대경로와 Start-Process -WindowStyle Hidden으로 띄운다.
   요약·판단 요청/생략/보류 이유·http://127.0.0.1:8778 주소만 짧게 보고한다.

별도 NH 기업선정 예약은 중지 상태다. 기업발굴 07:30·평가개선 16:00은 각자 역할 Work를 호출한다.
이 기기와 Codex 앱이 켜져 있어야 한다. 터미널을 열어 둘 필요는 없다.
손절은 시간 단위 점검으로 -4% 체결을 보장하지 않는다. 멈추려면 'NH 자동매매' 예약을 일시 중지한다.
